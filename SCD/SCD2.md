**SCD2 (Slowly Changing Dimension Type 2)** — это метод обновления измерений в хранилище данных, при котором для каждой версии записи измерения создаётся новая строка. Это позволяет сохранять полную историю изменений атрибутов и корректно связывать факты с состоянием измерения на момент транзакции.

**Когда использовать:**

- Нужен контекст на момент события (регион продавца в момент сделки)
    
- Критичные для бизнеса атрибуты (цены, кредитный рейтинг)
    
- Требования аудита
    
- Нужен анализ «срезов на дату»

### Целевая таблица содержит:

| Компонент     | Назначение                                                     |
| ------------- | -------------------------------------------------------------- |
| Surrogate Key | Уникальный идентификатор версии (генерируется в DWH)           |
| Natural Key   | Бизнес-ключ источника                                          |
| Атрибуты      | Версионируемые поля                                            |
| `valid_from`  | Начало действия версии                                         |
| `valid_to`    | Окончание действия (NULL / high-date для текущей)              |
| `is_current`  | Флаг актуальной версии (денормализация для производительности) |
**Инвариант[^1]**: для каждого natural key интервалы `[valid_from, valid_to)` не пересекаются и покрывают всю временную ось.

### ETL-логика

**1. Change detection.** Сравнение source с активными версиями target по версионируемым атрибутам. Критично: NULL-безопасное сравнение (`IS DISTINCT FROM` в PostgreSQL, hash-diff по конкатенации атрибутов для масштабируемости).

**2. Close current version.** Для изменившихся ключей:
```sql
UPDATE target SET valid_to = :load_date, is_current = FALSE
WHERE natural_key = :nk AND is_current = TRUE;
```

**3. Insert new version.** Для новых и изменившихся ключей — INSERT с новым surrogate key, `valid_from = :load_date`, `valid_to = NULL`, `is_current = TRUE`.

Операции 2–3 выполняются в одной транзакции; при конкурентной загрузке — с блокировкой по natural key, либо через идемпотентный MERGE.

### Соглашения о границах дат

Корректность SCD2 критически зависит от согласованности границ интервалов. Распространённое соглашение: `valid_from` включается в период действия строки, `valid_to` — исключается. При изменении в дату `D` предыдущая строка получает `valid_to = D`, новая — `valid_from = D`. Это предотвращает пересечение интервалов и гарантирует, что для любой даты ровно одна строка сущности является действительной. Выбор соглашения фиксируется в методологии хранилища и применяется единообразно для всей модели.

[^1]: Неизменное условие
