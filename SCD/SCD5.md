**SCD5 (Slowly Changing Dimension Type 5)** — это метод обновления измерений в хранилище данных, который сочетает мини-размерность (Mini-Dimension) типа 4 с текущей ссылкой типа 1 (Type 1 Outrigger) в основной таблице измерений. Такая конструкция позволяет одновременно сохранять исторические значения быстро меняющихся атрибутов и получать доступ к их текущим значениям напрямую из основной таблицы, без соединения с таблицей фактов .[](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/type-5/?source=post_page-----5e9f14ff912f-----------------------------------------)[](https://bbs.huaweicloud.com/blogs/143488)

**Ключевая характеристика:** основная таблица измерений содержит две ссылки на мини-размерность: одна (Type 2) фиксирует профиль на момент формирования строки и используется для исторических соединений через таблицу фактов; другая (Type 1) всегда указывает на актуальный профиль и перезаписывается при каждом изменении .[](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/type-5/?source=post_page-----5e9f14ff912f-----------------------------------------)[](https://repositoriocyt.unlam.edu.ar/bitstream/123456789/2421/1/M-I%20Osores.pdf#6#14#6)

**Когда использовать:**

- Быстро меняющиеся атрибуты (сегмент клиента, уровень дохода, кредитный рейтинг) имеют высокую частоту изменений и раздувают основную таблицу при использовании SCD2.
    
- Текущий профиль требуется часто и напрямую, без обращения к таблице фактов.
    
- Необходимо одновременно отвечать на вопросы «каким был профиль на момент транзакции» и «каков текущий профиль клиента».

## Реализация

**SCD5 использует три компонента:**

1. **Основная таблица (Base Dimension):** реализована по SCD2 для стабильных атрибутов; содержит внешний ключ мини-размерности (исторический профиль, Type 2) и текущий ключ мини-размерности (актуальный профиль, Type 1). Имена колонок должны различаться, чтобы избежать неоднозначности при запросах.
    
2. **Мини-размерность (Mini-Dimension):** содержит комбинации быстро меняющихся атрибутов; каждая уникальная комбинация получает суррогатный ключ; записи неизменяемы.
    
3. **Таблица фактов (Fact Table):** содержит внешний ключ на суррогатный ключ основной таблицы измерений.


**ETL-логика:**

**1. Обработка мини-размерности.** Для каждой входящей комбинации быстро меняющихся атрибутов выполняется поиск существующего ключа; при отсутствии — INSERT новой строки и генерация суррогатного ключа.

**2. Change detection.** Сравнение стабильных атрибутов и исторического ключа мини-размерности с активной записью основной таблицы (`is_current = TRUE`).

**3. Загрузка.**

- _Изменение стабильных атрибутов или исторического профиля (SCD2):_ закрыть текущую запись (`valid_to`, `is_current = FALSE`); вставить новую версию с историческим ключом мини-размерности во внешнем ключе и актуальным ключом — в текущем ключе.
    
- _Изменение только быстро меняющихся атрибутов:_ обновить поле текущего ключа в активной записи основной таблицы (Type 1 overwrite). Историческая ссылка в таблице фактов при этом не затрагивается.
    

**4. Обновление Type 1 Outrigger.** ETL-процесс обязан перезаписывать текущую ссылку на мини-размерность при каждом изменении назначения мини-размерности.

**Ключевое отличие от SCD4:** SCD4 не хранит текущий профиль в основной таблице — для его получения требуется соединение через таблицу фактов. SCD5 добавляет Type 1 Outrigger, устраняя эту зависимость .
