**SCD (Slowly Changing Dimension)** — подход к обновлению и поддержке данных, хранящихся в таблицах измерений, по мере их изменения.

| Тип          | Название / Суть                               | Что происходит с историей                                                                                                                                                                                  | Когда использовать                                                                                                                                     |
| ------------ | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SCD0**     | **Fixed / Original**                          | **Не меняется.** Значение фиксируется навсегда, обновления игнорируются.                                                                                                                                   | Данные, которые не должны меняться: дата рождения, оригинальный ID, код страны регистрации.                                                            |
| **[[SCD1]]** | **Overwrite**                                 | **История не сохраняется.** Новое значение просто перезаписывает старое.                                                                                                                                   | Исправление ошибок, обновление контактных данных. Важно: все старые факты начнут ссылаться на новое значение.                                          |
| **[[SCD2]]** | **Row Versioning**                            | **Полная история.** На каждое изменение создается новая строка с новым Surrogate Key, датами начала/конца (`valid_from` / `valid_to`) и флагом is_current.                                                 | **Самый популярный.** Нужен, когда важно знать состояние атрибута на момент совершения транзакции (например, где жил клиент при покупке).              |
| **[[SCD3]]** | **Previous Value**                            | **Ограниченная история.** Добавляется колонка «предыдущее значение» рядом с текущим.                                                                                                                       | Когда нужно сравнить «сейчас» только с «одним шагом назад». Используется редко.                                                                        |
| **[[SCD4]]** | **History Table**                             | **Разделение.** Текущие данные в основной таблице, вся история — в отдельной таблице.                                                                                                                      | Когда основная таблица должна быть легкой и быстрой, а история нужна редко.                                                                            |
| **[[SCD5]]** | **Mini-Dimension + Type 1 Outrigger (4 + 1)** | **Гибрид.** Волатильные атрибуты — в мини-размерности (как SCD4), история — через ссылку из фактов; поле `current_mini_dim_sk` в основной таблице перезаписывается по Type 1 (история по нему не ведётся). | Высокая волатильность атрибутов + быстрый доступ к **текущему** профилю без обращения к фактам. Плата — усложнение ETL и две ссылки на мини-измерение. |
| **[[SCD6]]** | **Hybrid (1+2+3)**                            | **Гибрид.** Сохраняет полную историю (как SCD2), но в каждой строке также хранит текущее и предыдущее значения.                                                                                            | Нужна максимальная гибкость: и исторические срезы, и быстрый доступ к текущему статусу.                                                                |

# Краткий дайджест: советы по каждому типу SCD

| Тип      | Главный совет                                                                           | Подводные камни                                                                                                                | Ключевой нюанс реализации                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SCD0** | Не трогай. Зафиксировал — и забыл.                                                      | Если ошиблись при загрузке — исправить можно только через SCD1 или перезаливку.                                                | Обычно это атрибуты, которые физически не могут измениться (дата рождения, исходный ID).                                                                                     |
| **SCD1** | Используй для **исправления ошибок** или в случае **нетребовательности к истории**.     | Все исторические факты «поедут» — старые транзакции начнут ссылаться на новое значение.                                        | Не требует новых ключей. Делай `UPDATE`, а не `INSERT`. Осторожно с ETL: нельзя просто перезаписать, если downstream уже посчитал агрегаты.                                  |
| **SCD2** | Стандарт де-факто. Если сомневаешься — бери SCD2.                                       | Раздувание таблицы + сложные джойны (нужно фильтровать по дате или флагу `is_current`).                                        | Обязательно: Surrogate Key, `valid_from`, `valid_to`, `is_current`. Для «закрытия» старой строки ставь `valid_to = дата_изменения - 1 день` (или `9999-12-31` для открытой). |
| **SCD3** | Бери только если бизнес явно просит «сравнить с прошлым».                               | Хранит лишь 1 шаг назад. При третьем изменении первое значение теряется навсегда.                                              | Добавляй колонки `current_value` и `previous_value`. Не масштабируется — при N изменениях нужны N колонок.                                                                   |
| **SCD4** | Используй, когда основная таблица должна оставаться быстрой.                            | Два источника правды — легко забыть синхронизировать историю и текущее.                                                        | Основная таблица = только актуальное. History-таблица = append-only. Джойн только когда реально нужна история.                                                               |
| SCD5     | Бери, если волатильные атрибуты «раздувают» измерение, но текущий профиль нужен быстро. | Две ссылки на мини-размерность — легко перепутать историческую и текущую; текущую ссылку забывают обновлять при смене профиля. | Мини-измерение (SCD4) + `current_mini_dim_sk` в основной таблице, перезаписываемый по SCD1. Имена колонок исторической и текущей ссылки — строго разные.                     |
| **SCD6** | Гибрид «всё в одном» — но не усложняй без необходимости.                                | Самая сложная логика загрузки. Легко получить рассинхрон между историческими и текущими колонками.                             | Комбинация: новая строка (SCD2) + колонка `current_value` (SCD1) + `previous_value` (SCD3). Идеален для BI, где нужны и срезы, и «актуальный статус» в одной строке.         |
