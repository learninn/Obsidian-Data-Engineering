**SCD4(Slowly Changing Dimension Type 4)** — это метод обновления измерений в хранилище данных, при котором актуальные версии измерений хранятся в одной таблице, а полная история изменений вынесена в отдельную таблицу истории.

Такое разделение позволяет сохранить высокую производительность запросов к текущему состоянию (hot path) и одновременно обеспечить полный аудит и анализ «на момент времени» без раздувания основной таблицы.

## Реализация

**SCD4 использует две таблицы:**

1. **Основная (Current):** реализована по SCD1 — ровно одна строка на естественный ключ, только актуальные значения. Остаётся компактной — критично для оперативной аналитики и соединений с фактами.
    
2. **История (History):** реализована по SCD2 — все предыдущие версии записей с метаданными времени (`valid_from`/`valid_to` или диапазон). Сюда попадают строки при изменении атрибутов.


Ключевое преимущество — **изоляция нагрузки**: ETL обновляет небольшую основную таблицу, а аналитические запросы к истории работают с отдельной таблицей, не блокируя основные операции.

**Когда использовать:**

- Текущие данные — hot path, история — cold path.
    
- Атрибуты меняются часто, основная таблица крупная.
    
- История нужна редко, но обязательна (аудит, регламент).
    
- Нужны простые запросы к текущему состоянию.
