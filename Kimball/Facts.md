**Fact table** — событие или наблюдение из **источника**, зафиксированное с числовыми мерами и ссылками на измерения. Он не строится на измерениях; измерения лишь дают контекст для его интерпретации.

**Что внутри:**

- **FK** на измерения (суррогатные ключи)
    
- **Measures** — числовые метрики
    
- **Degenerate dimension** — ключ без измерения (номер заказа)
    
- **Опционально:** дата/время события напрямую
    

**Свойства хорошего факта:**

- Аддитивный (можно суммировать) — revenue, quantity
    
- Полуаддитивный (нельзя суммировать по некоторым измерениям) — баланс, остаток
    
- Неаддитивный (нельзя суммировать) — процент, ratio, среднее
    

**Правило:** храни аддитивные метрики, вычисляй неаддитивные на лету.


**Типы фактов:**

| Тип                          | Grain              | Пример                              | Особенность                |
| ---------------------------- | ------------------ | ----------------------------------- | -------------------------- |
| Transaction                  | Каждое событие     | Продажа, клик                       | Растёт бесконечно          |
| Periodic snapshot            | Период             | Остаток на конец дня                | Фиксированный размер       |
| Accumulating snapshot        | Жизненный цикл     | Заказ: создан → оплачен → доставлен | UPDATE по мере продвижения |
|  [[Factless fact\|Factless]] | Событие без метрик | Посещение, наличие скидки           | Только FK + count          |

**Приколы:**

- Grain mismatch → дубли или потеря деталей
    
- Полуаддитивные метрики суммируют по ошибке → неверные числа
    
-  Забыли factless fact → потеряли факт события
    
- Accumulating snapshot без late-arriving handling → дыры в lifecycle
