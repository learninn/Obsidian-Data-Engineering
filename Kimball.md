**Kimball** —это методология проектирования DWH, при которой хранилище строится как набор **витрин по бизнес-процессам** на основе **[[dimensional modeling]]** (размерностного моделирования — "как проектировать звезду"), объединённых **[[conformed dimensions]]** (общими измерениями — "как связать витрины между собой").

**Ключевая идея:** DWH должен быть понятен бизнесу и отвечать на его вопросы через простые звёзды, а не через сложные нормализованные схемы.

**Цели:**

- Быстрый результат для бизнеса (недели, а не месяцы)
    
- Понятная модель для аналитиков и BI-инструментов
    
- Согласованность метрик через общие измерения
    
- Производительность за счёт денормализации
    
- Гибкость: новые вопросы → новые витрины

### Четыре шага проектирования

**Шаг 1. Выбрать бизнес-процесс.**  
Не «всё про клиента», а конкретно: продажи, возвраты, инвентарь, маркетинг, поддержка.

**Шаг 2. Определить grain (уровень детализации).** 
Одна строка факта = что именно?

- Одна позиция заказа?
    
- Один заказ?
    
- Один день по клиенту и товару?


**Правило:** grain определяет всё. Ошибёшься — переделывать всю звезду.

**Шаг 3. Определить измерения.**  
Какие контексты описывают факт? Дата, клиент, товар, магазин, сотрудник, промо.

**Шаг 4. Определить метрики (facts).**  
Что измеряем? Сумма, количество, маржа, скидка, себестоимость.


### Быстрые правила (TL;DR)

**Dimensional modeling:**

1. Сначала grain, потом всё остальное
    
2. Звезда > снежинка (снежинка только при необходимости)
    
3. Измерения денормализованы
    
4. Суррогатные ключи — везде
    
5. Аддитивные метрики храни, неаддитивные вычисляй
    
6. Не смешивай grain'ы в одной таблице
    
7. Тесты на данные — обязательны
    
8. Партиционируй факты по дате
    

**Conformed dimensions:**

1. Один клиент = один `client_sk` везде
    
2. Conformed dimensions — не роскошь, а необходимость
    
3. Governance без владельца — бардак
    
4. Bus Matrix — карта проекта
    
5. Shrunken — те же ключи, меньше атрибутов
    
6. Role-playing — view, не копия
    
7. NULL handling — одинаков везде
    
8. Документируй определения — иначе три «клиента»
