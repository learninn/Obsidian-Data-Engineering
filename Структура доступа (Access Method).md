**Структуры доступа (Access Methods)** — это набор алгоритмов и структур данных, определяющих способ организации, хранения и извлечения записей из базы данных. Они являются надстройкой над физическим уровнем хранения и обеспечивают эффективную навигацию без необходимости полного сканирования данных.


> [!Терминологическое замечание]
>  В литературе и документации термин **«индекс»** используется в двух смыслах.
>  **В логическом смысле индекс** — это **объект схемы данных**, создаваемый для ускорения поиска по одному или нескольким столбцам.
>  **В физическом смысле индекс** — это **конкретная структура доступа** (например, B-дерево), **реализующая это ускорение**.
>  **Настоящая статья** описывает структуры доступа как **физические механизмы**; **логические индексы** являются их **пользовательской проекцией**.


### Классификация по целевой нагрузке

Структуры доступа различаются по доминирующему сценарию использования:

- **Read-optimized**: оптимизированы для минимизации задержки поиска. Обновления выполняются на месте (in-place) и могут требовать реорганизации структуры. Характерный представитель — B-дерево (B-tree / B+tree). Обеспечивает логарифмическую сложность поиска и эффективный диапазонный доступ.
    
- **Write-optimized**: оптимизированы для высокой пропускной способности записи. Обновления выполняются последовательной дозаписью (append-only), поиск требует слияния нескольких версий структуры. Характерный представитель — LSM-дерево (Log-Structured Merge-tree). Стоимость чтения выше, стоимость записи ниже.


### Основные типы структур

**B-дерево (B-tree / B+tree)**  
Сбалансированное дерево поиска, в котором все листовые узлы находятся на одном уровне и связаны между собой для последовательного сканирования. Поддерживает точечный и диапазонный поиск, а также упорядоченный обход. Обновления выполняются в существующих страницах. Является структурой по умолчанию для большинства реляционных СУБД.

**Хеш-таблица (Hash)**  
Структура, отображающая ключ в адрес через хеш-функцию. Обеспечивает доступ за O(1) для операций точного совпадения (equality). Не поддерживает диапазонный поиск и упорядоченный обход. Эффективна для нагрузок с преобладанием точечных выборок по ключу.

**LSM-дерево (Log-Structured Merge-tree)**  
Структура, оптимизированная для последовательной записи. Вставки и обновления накапливаются в упорядоченном буфере в памяти (memtable) и периодически сбрасываются на диск в виде неизменяемых отсортированных файлов (SSTable). Поиск требует проверки нескольких уровней и фонового слияния (compaction). Применяется в системах с интенсивной записью.

**Min-Max / Zone Map (BRIN)**  
Разреженная структура, хранящая минимальное и максимальное значения для диапазона физически смежных страниц. Позволяет пропускать целые блоки данных при выполнении запросов с условиями на диапазон. Эффективна для больших таблиц с коррелированными данными и низкой кардинальностью.

**Инвертированный индекс (Inverted Index)**  
Структура, отображающая терм (токен) в список идентификаторов документов или записей, содержащих этот терм. Применяется для полнотекстового поиска и поиска по вложенным структурам (массивам, JSON). Поддерживает операции вхождения (containment) и пересечения множеств.

### Компромиссы (Trade-offs)

Выбор структуры доступа определяется балансом трёх ресурсов:

- **Стоимость чтения**: определяется числом операций ввода-вывода, необходимых для нахождения записи. B-дерево минимизирует глубину обхода; хеш-таблица минимизирует число обращений при точном совпадении; LSM-дерево может требовать проверки нескольких уровней.
    
- **Стоимость записи**: определяется необходимостью реорганизации структуры. B-дерево требует поддержания порядка и балансировки; LSM-дерево минимизирует стоимость за счёт последовательной записи; хеш-таблица требует расширения при заполнении.
    
- **Пространственная эффективность**: определяется служебными данными и заполнением страниц. B-дерево обычно поддерживает заполнение страниц на 50–100%; LSM-дерево имеет накладные расходы на многоуровневое хранение; разреженные структуры (Min-Max) минимальны по объёму, но дают приблизительный ответ.
