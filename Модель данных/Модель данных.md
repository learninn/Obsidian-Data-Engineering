**Модель данных** — формальное описание представления данных в СУБД и операций над ними (состав объектов, их связи и допустимые операции), которое включает, по меньшей мере, три аспекта:

* аспект структуры: методы описания типов и логических структур данных в БД
	
* аспект манипуляции: методы манипулирования данными
	
* аспект целостности: методы описания и поддержки целостности БД[^1]

### Модели данных:

| Модель данных                                                                        | Краткое описание                                                                                                                                                                                                                                                                                                                                | Типичная область применения                                                                                                                                                        |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **[[Реляционная модель данных\|Реляционная]]**                                       | Данные организованы в таблицы (отношения) со строго заданной схемой; связи устанавливаются через первичные и внешние ключи. Управление осуществляется с помощью SQL, поддерживаются ACID-транзакции.                                                                                                                                            | Транзакционные системы (банки, ERP, интернет-магазины), учет и системы с высокими требованиями к целостности данных.                                                               |
| **Иерархическая**                                                                    | Данные представлены в виде древовидной структуры «родитель-потомок», где у каждого потомка только один родитель. Обеспечивает быстрый доступ при строгой навигации по структуре.                                                                                                                                                                | Файловые системы, реестр Windows, некоторые телекоммуникационные и авиационные системы бронирования (исторически).                                                                 |
| **[[Объектно-ориентированная модель данных\|Объектная / Объектно-ориентированная]]** | Данные хранятся в виде объектов, напрямую соответствующих объектам в объектно-ориентированном программировании (классы, атрибуты, методы, наследование).                                                                                                                                                                                        | Сложные инженерные расчеты (CAD/CAM), системы мультимедиа, научные исследования, где важна прямая интеграция с ООП-кодом.                                                          |
| **[[Объектно-реляционная модель данных\|Объектно-реляционная]]**                     | Гибридная модель: реляционная основа дополнена объектными расширениями (пользовательские типы данных, наследование, сложные методы).                                                                                                                                                                                                            | Приложения, которым нужна надежность реляционных БД, но требуется хранить сложные структуры данных (например, геоданные, мультимедиа).                                             |
| **[[Графовая модель данных\|Графовая]]**                                             | Данные представлены как узлы (сущности) и ребра (связи). Оптимизированы для выполнения сложных запросов по связям (обход графа).                                                                                                                                                                                                                | Социальные сети, рекомендательные системы, обнаружение мошенничества, анализ связей и логистика.                                                                                   |
| **[[Мультимодельная модель данных\|Мультимодельная]]**                               | Единая СУБД, которая нативно поддерживает несколько моделей данных (например, документную, графовую и реляционную) в одном движке с общей транзакционной логикой.                                                                                                                                                                               | Проекты, где необходимо обрабатывать разнородные данные (JSON, графы, пространственные данные) без развертывания нескольких разных систем и сложной синхронизации.                 |
| **[[Векторная модель данных\|Векторная]]**                                           | Данные хранятся в виде векторов — плотных массивов чисел (обычно сотни или тысячи измерений), которые кодируют семантику объектов (текста, изображений, аудио). Поиск основан не на точном совпадении, а на вычислении схожести (косинусное расстояние, евклидово расстояние) с использованием приближённых алгоритмов ближайших соседей (ANN). | Семантический поиск, RAG (генерация с дополненной выборкой), рекомендательные системы, подбор похожих изображений/аудио, дедупликация и кластеризация неструктурированных данных . |
| **[[Документная модель данных\|Документная]]**                                       | Данные хранятся в виде документов (обычно JSON, BSON или XML) с гибкой, заранее не заданной схемой. Каждый документ — самодостаточная единица, содержащая вложенные структуры и массивы; связи чаще выражаются через вложенность, а не через внешние ключи.                                                                                     | Контент-менеджмент, каталоги товаров с разнородными атрибутами, профили пользователей, мобильные и веб-приложения с быстро меняющейся схемой, прототипирование.                    |

[^1]: **Целостность базы данных (database integrity)** — соответствие имеющейся в БД информации её внутренней логике, структуре и всем явно заданным правилам.
	Каждое правило, налагающее некоторое ограничение на возможное состояние базы данных, называется **ограничением целостности**.
