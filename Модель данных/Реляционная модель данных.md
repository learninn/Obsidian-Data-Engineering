**Реляционная модель данных** — логическая модель данных, в которой:
* данные организованы в виде **отношений**
	
* над данными определены операции реляционной алгебры и реляционного исчисления

Кроме того, в состав реляционной модели данных включают теорию **[[Normal Form (NF)|нормализации]]**.

## Структурная составляющая

**Отношение**[^1] — множество кортежей, соответствующих одной схеме. Схема отношения — имя отношения + множество атрибутов с доменами.

- **Атрибут** — именованный столбец; имя уникально в пределах схемы.
    
- **Домен** — множество атомарных значений, из которого берутся значения атрибута (тип + ограничения).
    
- **Кортеж** — строка; упорядоченный набор значений атрибутов.
    
- Отношение — это **множество**[^2], поэтому: строки не упорядочены, дубликатов нет[^3], столбцы не упорядочены (доступ по имени).


**Атомарность** значения: в ячейке — одно неделимое значение (никаких списков/вложенных таблиц). Это требование **1NF** и **фундамент модели**

## Целостность (три класса ограничений)

- **Доменная целостность** — каждое значение принадлежит домену атрибута (тип, диапазон, NULL/NOT NULL, CHECK).
    
- **Сущностная (ключевая) целостность** — первичный ключ уникален и не содержит NULL; кортеж идентифицируется ключом.
    
- **Ссылочная целостность** — значение внешнего ключа либо `NULL`, либо ссылается на значение, которое уникально в родительской таблице.

**Ключ** — это специальное поле (или набор полей), которое используется для однозначной идентификации записей в таблице, связи между разными таблицами и обеспечения целостности данных.

**Ключи:**

- **Суперключ** — набор атрибутов, уникально идентифицирующий кортеж (может быть избыточным).
    
- **Потенциальный (candidate) ключ** — минимальный суперключ.
    
- **Первичный ключ** — выбранный потенциальный ключ.
    
- **Альтернативный** — остальные потенциальные ключи.
    
- **Внешний ключ** — атрибут(ы), ссылающийся на ключ другого отношения.
    
- **Естественный (бизнес) vs суррогатный** ключ (значимые данные vs искусственный идентификатор).

## Реляционная модель лежит в основе [[Реляционная БД|реляционных СУБД]]


[^1]: **Отношение (в математике)** — множество уникальных кортежей, где каждый элемент взят из своего допустимого набора значений.

[^2]: **Множество** — совокупность каких-либо объектов (элементов), рассматриваемых как единое целое

[^3]: Отсутствие дубликатов обеспечивает однозначную идентификацию описания состояния сущности
