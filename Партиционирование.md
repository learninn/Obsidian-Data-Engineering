**Партиционирование (секционирование)** — это разделение одной большой таблицы (или индекса) на несколько физических частей (партиций), которые для приложения выглядят как единая таблица. Каждая партиция хранится отдельно и может управляться независимо.

**Преимущества:**

- **Производительность:** запросы читают только нужные партиции (partition pruning[^1]), вместо всей таблицы.
    
- **Управляемость:** можно быстро удалять/архивировать старые данные через `DROP PARTITION` вместо долгого `DELETE`.
    
- **Обслуживание:** индексы, бэкапы и сборка мусора работают с отдельными частями.
    
- **Распределение нагрузки:** партиции можно разнести по разным дискам/серверам.

### Основные стратегии

* **Range** — по диапазону значений (например, по дате: `2024-01`, `2024-02`). Самая частая для логов и временных рядов.
    
* **List** — по явному списку значений (например, по региону или стране).
    
* **Hash** — по хешу ключа, для равномерного распределения (например, по `user_id`).
    
* **Composite** — комбинация нескольких стратегий (range + hash).

### Ключевые понятия

- **Partition key** — столбец(ы), по которым определяется, в какую партицию попадёт строка.
    
- **Partition pruning** — оптимизатор отбрасывает партиции, не подходящие под условие запроса.
    
- **Глобальные vs локальные индексы** — локальный индекс строится на каждую партицию, глобальный — на всю таблицу.

### Ограничения и подводные камни

- Не все запросы могут использовать pruning (например, при функциях над ключом).
    
- Слишком много мелких партиций вредит планировщику (overhead на метаданные).
    
- Необходимо заранее продумывать стратегию создания новых партиций (автоматизация).
