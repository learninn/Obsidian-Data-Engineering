**Операторы управления транзакциями (Transaction Control Language)** — это подмножество команд SQL, предназначенное для управления транзакциями в базе данных. TCL позволяет объединять несколько операций (например, вставку, обновление или удаление данных) в единую логическую единицу работы, которая либо выполняется полностью, либо отменяется целиком, что обеспечивает целостность и согласованность данных.

TCL-команды напрямую управляют тем, как изменения, внесённые с помощью [[DML|DML-операций]], применяются или отменяются.

### Основные операторы

| Команда                       | Назначение                                                                                                                                                | Пример                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `SET TRANSACTION`             | Устанавливает характеристики текущей транзакции: уровень изоляции (`READ COMMITTED`, `SERIALIZABLE` и др.) или режим доступа (`READ WRITE`, `READ ONLY`). | `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;` |
| `BEGIN` / `START TRANSACTION` | Явно начинает новую транзакцию. Все последующие DML-операции выполняются в её рамках до `COMMIT` или `ROLLBACK`.                                          | x`BEGIN;`  <br>`START TRANSACTION;`             |
| `COMMIT`                      | Фиксирует транзакцию. Все изменения становятся постоянными и видимыми другим пользователям. Отменить их после `COMMIT` нельзя.                            | `COMMIT;`                                       |
| `ROLLBACK`                    | Откатывает всю текущую транзакцию. Все изменения с момента последнего `COMMIT` (или начала транзакции) отменяются.                                        | `ROLLBACK;`                                     |
| `SAVEPOINT`                   | Создаёт точку сохранения внутри транзакции, к которой можно откатиться, не отменяя всю транзакцию.                                                        | `SAVEPOINT sp1;`                                |
| `ROLLBACK TO`                 | Откатывает транзакцию до указанной точки сохранения (`SAVEPOINT`), не завершая транзакцию полностью.                                                      | `ROLLBACK TO sp1;`                              |
| `RELEASE SAVEPOINT`           | Удаляет ранее созданную точку сохранения. Транзакция при этом не завершается и не фиксируется.                                                            | `RELEASE SAVEPOINT sp1;`                        |

### Пример использования

```sql
-- 1. Настраиваем параметры для будущей транзакции (уровень изоляции и режим записи)
SET TRANSACTION ISOLATION LEVEL READ COMMITTED READ WRITE;

-- 2. Инициируем (открываем) транзакцию
START TRANSACTION;

-- Шаг А: Списываем 1000 рублей со счета отправителя
UPDATE accounts 
SET balance = balance - 1000 
WHERE account_id = 101;

-- Шаг Б: Начисляем 1000 рублей на счет получателя
UPDATE accounts 
SET balance = balance + 1000 
WHERE account_id = 102;

-- 3. Создаем контрольную точку перед рискованной операцией (списание комиссии)
SAVEPOINT fee_charging;

-- Шаг В: Пробуем списать комиссию 50 рублей
UPDATE accounts 
SET balance = balance - 50 
WHERE account_id = 101 AND balance >= 50;

-- (В реальности здесь идет проверка приложения: если баланса не хватило для комиссии,
-- или банк-партнер вернул ошибку, мы отменяем ТОЛЬКО списание комиссии)

-- 4. Частичный откат: отменяем списание комиссии, но сохраняем сам перевод денег
ROLLBACK TO SAVEPOINT fee_charging;

-- 5. Фиксируем транзакцию: перевод 1000 рублей успешно сохранен в базе данных
COMMIT;
```
